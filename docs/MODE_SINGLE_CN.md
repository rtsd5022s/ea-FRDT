# 普通模式（单线程）

## 什么是普通模式

普通模式就是单线程跑一个浮点格式。不碰多线程，不起 worker 池，不起监视器。主循环就在主线程里，走一步打一步，直到溢出或下溢。

命令行不带 `-m all` 就是普通模式。比如：

```
float_inf_walk 0 -m fp32
float_inf_walk 0 -m dec64 -k 1.5
float_inf_walk 0 -m x87 -t 10
```

普通模式的特点是简单直接。没有线程调度开销，没有缓存行对齐的 WorkerSlot，没有监视器线程。就是一个 for 循环，每步做乘法、检查溢出、打印一行。

## 启动流程

main 函数进来先做什么：

1. Windows 下调 `timeBeginPeriod(1)` 把系统定时器分辨率提到 1ms，设控制台 UTF-8 编码，开 ANSI 转义序列处理
2. 注册 SIGINT 信号处理函数（Ctrl+C）
3. 解析命令行参数
4. 根据 `-m` 参数选格式
5. 调对应的 drive 函数开始走

参数解析在 main 里，按位置参数和可选参数分开。第一个位置参数是 delay_ms（每步限速毫秒），后面是 `-x value` 形式的可选参数。

## 参数解析

普通模式能识别的参数：

**`-m <format>`**：选格式。默认 f32。可选值见格式列表。

**`-a <start>`**：起点。默认 1.0。可以是：
- 纯数字：`-a 1.5`
- 科学计数法：`-a 1.5e-3`
- 十六进制 Raw：`-a 0x3f800000`
- 关键字：`min-normal`（最小正规格化数）、`max-finite`（最大有限数）
- 负数：`-a -1`

**`-k <factor>`**：每步倍率。默认 1.02。大于 1 往上走会溢出，小于 1 往下走会下溢。支持科学计数法。

**`-g <stepmode>`**：步进模式。默认是倍率模式（×1.02）。可选：
- `mululp`：每步 ×(1+1ULP)
- `addulp`：每步 +1ULP

选了 mululp 或 addulp 后，不再显示 x1.02 倍率。

**`-f <fmt>`**：显示格式。默认工程计数法。可选：
- `eng`：工程计数法，指数是 3 的倍数
- `sci`：科学计数法
- `full`：完整显示所有有效数字

**`-d <n>`**：小数位数。默认 6。范围 0 到 100。`-d -1` 表示完整显示。

**`--bits <mode>`**：括号内位表示。默认 off。可选：
- `hex`：十六进制位模式
- `bin`：二进制位模式，分段显示
- `off`：不显示

**`-t <sec>`**：超时秒数。默认 0（不限制，走到溢出/下溢）。

**`-l <n>`**：循环次数。默认 1。`-l -1` 无限循环。

**`-s`**：从最小非规格化数开始。

**`-q`**：静默模式，不实时打印，跑完直接出结果。

**`--lang <zh|en>`**：界面语言。

## 主循环

普通模式的主循环在 drive 函数里。drive 是模板函数，按格式类型分发。

伪代码：

```
当前值 = 起点
步数 = 0
t0 = now
while (没退出) {
    if (超时) break
    旧值 = 当前值
    当前值 = 当前值 * 倍率    // 或 addulp/mululp
    步数++
    if (溢出) {
        打印 overflow->inf
        break
    }
    if (下溢) {
        打印 underflow->0
        break
    }
    if (每步刷新) {
        打印当前值
    }
    if (delay_ms > 0) {
        sleep(delay_ms)
    }
}
打印最终结果
```

## 溢出判断

每种格式判断溢出的方式不同：

**原生格式（FP16/FP32/FP64）**：乘完后检查 `std::isinf(x)`。如果是 inf，说明溢出了。

**自写位级格式（FP4/FP6/FP8/BF16/TF32）**：检查指数字段是否全 1。如果乘完后指数变成全 1，说明溢出。或者检查 raw 值是否超过最大有限数的 raw。

**x87/FP128**：纯软件，检查指数是否超过 Emax。如果指数大于 Emax，标记溢出。

**BID 十进制**：检查 `exp10 + digits - 1 > Emax`。不是简单比 exp10，因为系数乘完后可能进位，需要加上有效位数。Emax 对 Dec32 是 96，Dec64 是 384，Dec128 是 6144。

**DPD 十进制**：和 BID 一样的溢出判断，但编解码走 DPD 路线。

## 下溢判断

下溢就是值太小，接近零了。

**原生格式**：乘完后检查 `x == 0` 或者是最小非规格化数。如果值小于最小正规格化数，进入非规格化区间。继续乘直到变成 0。

**自写位级格式**：检查指数字段是否全 0。如果指数全 0 且尾数全 0，就是零。

**十进制格式**：检查 exp10 是否小于 emin。emin 对 Dec32 是 -95，Dec64 是 -383，Dec128 是 -6143。

## 打印格式

每步打印一行，格式：

```
FP32: 1.234567e+10   4481 steps
```

或者带位表示：

```
FP32: 1.234567e+10   [3f800000]
```

工程计数法的尾数固定 6 位小数。科学计数法不强制指数是 3 的倍数。完整显示不截断。

静默模式 `-q` 不打印中间步骤，只在最后打一行总结。

## 超时控制

`-t 10` 表示 10 秒后停。超时检查在每步循环开始时：

```
if (g_timeout_sec > 0) {
    elapsed = now - t0
    if (elapsed >= g_timeout_sec) break
}
```

超时后打印 `timeout` 退出原因，然后打结果。

## 循环

`-l 3` 表示跑 3 遍。每遍跑完（溢出或下溢）后重置当前值到起点，重新开始。3 遍跑完后打总结。

`-l -1` 无限循环，必须配合 `-t` 使用。

## Ctrl+C

按 Ctrl+C 时，信号处理函数设置 `g_sigint = true`。主循环在下一步检查到这个标志，打印"程序提前退出（收到 Ctrl+C）"，然后打结果退出。

## 单线程格式链

普通模式一次只跑一个格式。如果要看多个格式的结果，得跑多次命令行。这是和 `-m all` 并发模式最大的区别。

每个格式的步数基准（×1.02 从 1 出发）：
- FP4/FP6/FP8：1 步就溢出
- FP16：574 步
- BF16：3913 步
- TF32：4623 步
- FP32：4481 步
- Dec32：11279 步
- FP64：35843 步
- Dec64：44767 步
- x87/FP128：573521 步
- Dec128：714521 步
- DPD32：11279 步
- DPD64：44767 步
- DPD128：721963 步

这些数字是固定的，因为从 1.0 每次乘 1.02 到溢出，走多少步是由格式的 Emax 决定的。

## 速度统计

普通模式下程序会算当前速度：步数除以已用时间。比如跑了 4481 步用了 1 秒，速度就是 4481 steps/s。

速度不是恒定的。开头几步快，因为值小，乘法快。越往后值越大，乘法越慢（尤其纯软件的 x87/FP128/DPD），速度会下降。

## 延迟参数

第一个位置参数是 delay_ms，每步之间的等待时间。`float_inf_walk 0` 是不延迟。`float_inf_walk 10` 是每步等 10ms，这样能慢动作看每步的值变化。

延迟对性能测试没意义，但对观察中间过程有用。想仔细看每一步走到哪了，加延迟慢慢走。

延迟用 `std::this_thread::sleep_for` 实现，精度是毫秒级。Windows 下因为开了 `timeBeginPeriod(1)`，睡眠精度到 1ms。

## 帮助信息

`-h` 打印帮助信息，列出所有参数和格式。双语切换 `--lang` 控制显示中文还是英文。

帮助信息里格式分类：
- 原生：f16 f32 f64
- 自写位级：fp4 fp6 fp8-e4m3 fp8-e5m2 bf16 tf32
- 纯软件：x87 fp128
- 十进制：dec32 dec64 dec128 dpd32 dpd64 dpd128
- all：并发跑全部

## 性能

普通模式没有线程开销，没有锁，没有缓存行对齐。纯计算。瓶颈在浮点运算本身。

x87 和 FP128 是纯软件整数运算，比原生 FP64 慢。DPD 格式因为有查表和 declet 处理，比 BID 慢。

## 退出原因

程序退出时打一行退出原因：

- `overflow->inf`：溢出到无穷大
- `underflow->0`：下溢到零
- `timeout`：超时
- `cancelled`：DPD 警告确认时取消
- `sigint`：收到 Ctrl+C

每种退出原因的打印位置不同。溢出/下溢是在主循环检测到时打印。超时是在每步检查时检测到。sigint 是信号处理函数里设标志，主循环下一步看到。

## 格式选择指南

选哪个格式看你想测什么：

- **快速测试**：FP32 或 FP64，步数少，几秒出结果
- **低精度**：FP4/FP6/FP8，步数极少，看精度损失
- **高精度**：FP128 或 Dec128，步数多，看长时间运行稳定性
- **十进制**：Dec32/Dec64/Dec128（BID）或 DPD 系列，看十进制浮点行为
- **x87**：看 80 位扩展精度的行为

不同格式的 Emax 不同，从 1.0 乘 1.02 到溢出的步数差异很大。小格式几步就炸，大格式走几十万步。

## 输入校验

程序对非法输入有校验：

- 未知格式名：报错退出
- 倍率为 0：报错（0 会立刻下溢）
- 倍率为负：报错
- 起点无法解析：报错
- 超时为负：报错
- 循环次数为 0：报错（0 没意义）

非法输入不会导致程序崩溃，而是打印错误信息退出。

## 命令行示例

常用命令行组合：

```
# FP32 默认跑
float_inf_walk 0 -m fp32

# FP16 从最大值递减
float_inf_walk 0 -m fp16 -a max-finite -k 0.5

# Dec64 限时 10 秒
float_inf_walk 0 -m dec64 -t 10

# FP128 静默跑
float_inf_walk 0 -m fp128 -q

# 无限循环加超时
float_inf_walk 0 -m fp32 -l -1 -t 30
```

## 数据输出

程序输出到 stdout。错误信息到 stderr。可以重定向到文件：

```
float_inf_walk 0 -m fp32 -q > result.txt
```

静默模式下输出只有最后一行结果，方便脚本处理。

## 退出码

程序退出码：
- 0：正常退出（溢出/下溢/超时）
- 1：参数错误或运行时错误

## 颜色输出

程序用 ANSI 颜色代码打印输出：
- 青色横幅
- 灰色信息
- 绿色正常
- 黄色警告
- 红色错误

不支持 ANSI 的终端会显示乱码。静默模式 `-q` 减少颜色输出。

## 语言

`--lang zh` 中文界面，`--lang en` 英文界面。所有界面文字走 `tr()` 双语函数。

## 注意事项

1. 普通模式默认每步都打印，步数多的格式（FP128 几十万步）会刷屏。加 `-q` 静默。
2. `-k 1.02` 从 1.0 出发，FP32 要走 4481 步才溢出。FP128 要走 57 万步。
3. `-k 0.5` 递减，从 1.0 出发会很快下溢到 0。
4. `-a max-finite` 配合 `-k 0.5` 从最大值往下走，看从最大数到零要多少步。
5. `-s` 从最小非规格化数开始，会先走过一段非规格化区间才到正规格化。
6. DPD 格式第一次跑会弹警告，按 y 确认。
7. `-d -1` 完整显示，小数位数不截断，适合看精确值。
8. `--bits bin` 二进制分段显示，符号/指数/尾数用空格隔开。
9. 负数起点配合 `-k 1.02` 会先走到 -inf。
10. 普通模式不绑核，OS 自动调度，可能在核心间漂移。
11. `-g mululp` 模式步长随值变大而自动变大，因为 ULP 大小取决于当前量级。
12. `-g addulp` 模式步数最多，因为每步只动一个最小单位。FP32 的 addulp 要走约 2^23 ≈ 800 万步。
13. 显示格式 `-f eng` 工程计数法指数是 3 的倍数，`-f sci` 科学计数法不强制。
14. `-a 0x3f800000` 是 FP32 的 1.0 原始位模式，可以从任意位模式开始。
15. 程序退出时打印最终步数和总耗时。静默模式下只打最后一行结果。
