# UInt256 / UInt128 技术原理

## 定位

`include/uint256.h` 与 `include/uint128.h` 是两个**独立 drop-in single-header 库**，只依赖 `<cstdint>`/`<cstring>`/`<string>`，不依赖任何项目内其他头文件。`#include "uint256.h"` 即可在任意 C++23 GCC/Clang 工程里使用。

最初它们只是 dec128(BID) 行走器的内部零件（四个 64 位字、只有乘和除以 10），随着 BID 编码层补全、dec128 舍入逻辑需要进位链、以及独立自测的需要，逐步长成了完整的小整数库：运算符重载、十进制字符串互转、移位、通用小整数除法、位长查询，全部带 10 项断言的独立 self-test。

## 为什么需要大整数

dec128 的系数是 110 位二进制整数（IEEE 754-2008 BID 布局）。从 `1.0` 出发每步乘 `1.02`，等价于系数乘以 `102`、指数减 `2`，然后规范化。两个 110 位整数相乘，中间结果是 220 位。C++ 标准里最大无符号整数是 `uint64_t`；编译器扩展 `__int128` 并非所有工具链都提供，而且它只能装 128 位，220 位还是装不下。

所以必须自己造一个大整数。选了 **UInt256**：四个 `uint64_t` 字，共 256 位。256 位够装 110×110=220 位的乘积，还留 36 位余量给进位。`UInt128` 是对称的两个字版本，服务于 x87/FP128 的尾数中间积辅助（那里 128 位够）。

## 数据结构

```cpp
struct UInt256 {
    std::uint64_t w[4] = {0,0,0,0};
};
```

四个字，`w[0]` 是最低位（least significant），`w[3]` 是最高位。这种小端字序（little-endian word order）是大整数算法的标准选择：进位从 `w[0]` 向 `w[3]` 传播，索引递增方向就是进位传播方向，写循环时不容易搞反。`UInt128` 同理，`w[0]`/`w[1]` 两个字。

构造函数：`UInt256()` 全零；`UInt256(v)` 把 64 位数塞进 `w[0]`；`UInt256(w0,w1,w2,w3)` 四字全给。

## mul64：64×64 怎么拆成 32×32

最底层的运算是 `mul64(x, y, lo, hi)`：输入两个 64 位无符号整数，输出 128 位乘积的低 64 位和高 64 位。

这个头文件不用 `__int128`，原因有三：第一，可移植性；第二，教学目的——拆成 32 位乘法能看清楚 128 位乘积到底怎么来的；第三，在 64 位 x86 上，编译器看到 32 位乘法链会自己识别成 `mulx`（ADX）或 `mul`（经典 MUL），生成的机器码和手写 `__int128` 几乎一样。

拆法是标准 Schoolbook：

```
x = x1 * 2^32 + x0
y = y1 * 2^32 + y0
x*y = x1*y1 * 2^64 + (x1*y0 + x0*y1) * 2^32 + x0*y0
```

四个 32×32 乘积拼中间项，整个过程没有分支，固定 6 条算术指令。在 x86-64 上 GCC/Clang 会把它折叠成一条硬件乘法指令。

## mul128 与 mul：两层乘法

- `mul128(a_lo, a_hi, b_lo, b_hi)`：两个 128 位数相乘，输出 256 位。四次 `mul64` 调用 + 进位传播。
- `mul(a, b)`：完整 256×256 → 256（截断低 256 位，高位进位丢弃）。双重循环 `i=0..3, j=0..3-i`，每次 `mul64(a.w[i], b.w[j], lo, hi)`，把 `lo` 加到 `r.w[i+j]`，`hi` 带进位到下一字。

进位检测用无符号回绕：`c = a + b; carry = (c < a) ? 1 : 0;`。等价于 x86 `add` 自动设的 CF 位，但 C++ 不能直接读 CF，只能这么写。编译器识别成 cmov，不真分支。

## 小整数算术

| 方法 | 作用 |
|---|---|
| `inc()` | 原地加 1，沿 `w[0]→w[3]` 传播进位 |
| `add_small(v)` | 原地加一个 64 位小整数，带进位链 |
| `mul_small(m)` | 原地乘一个 64 位小整数，返回溢出进位 |
| `div10()` | 原地除以 10，返回余数（dec128 规范化热路径，常数优化） |
| `div_small(d)` | 通用小整数除法，逐位试商（64 次 bit 迭代 per word），返回余数 |

`div10` 是 `div_small(10)` 的特化版：用 `2^64/10 = 0x1999999999999999`、`2^64%10 = 6` 这两个常数直接拼商和余数，编译器把 `w[i]/10` 和 `w[i]%10` 优化成乘法+移位，不真调除法指令。

## 比较与位工具

| 方法 | 作用 |
|---|---|
| `is_zero()` | 四字或起来判零 |
| `cmp(o)` | 从 `w[3]` 往 `w[0]` 逐字比，返回 -1/0/+1 |
| `eq/lt/gt/le/ge(o)` | cmp 的便捷包装 |
| `ge(v)` | 判断 `this >= v`（v 是 64 位数），高三个字任一非零即 true |
| `bit_length()` | 最高位位置 +1，零返回 0（用 `__builtin_clzll`） |

自由函数运算符 `== != < > <= >=` 全给。

## 移位

- `shr(n)`：逻辑右移 n 位。`n/64` 个字搬走，`n%64` 位跨字拼接。
- `shl(n)`：逻辑左移 n 位，对称。

n≥256 返回零；n≤0 返回自身。

## 字符串互转

- `to_string()`：反复 `div10()` 把十进制位从低到低吐到缓冲区，反转输出。256 位最多 78 位十进制数字。
- `to_hex_string()`：四字按 `w[3]→w[0]` 顺序每字 16 个 hex nibble，前导零剥掉。
- `from_dec_string(s)`：从十进制字符串构造，逐字符 `mul_small(10) + add_small(digit)`。

## 自由函数运算符

```cpp
UInt256 a(12345), b = UInt256::mul128(lo, hi, lo, hi);
a += b;
UInt256 c = a + b;
UInt256 d = a * b;
if (a > b) { ... }
```

`operator+`、`operator+=`、`operator*`（走 `mul`）全给。没有 `-`/`-=`/`/`（减法和通用大除法按需再补）。

## 为什么不用 Karatsuba 或 FFT

256 位乘法如果用 Karatsuba，可以把 4 次 `mul64` 降到 3 次。但 256 位太小：Karatsuba 的递归开销在 n=4 时反而比 Schoolbook 慢。n 到 16 字以上 Karatsuba 才开始划算，FFT 要到几千位才有用。

dec128 参考步数约 71 万量级，每步一次乘法，纯乘法层约 2130 万条指令、数秒量级（不含 div10/舍入/显示/调度）。端到端实测见 BASELINE_CN.md。

## 和 BID/DPD 的关系

UInt256 只服务于 BID 路线的 dec128。DPD 路线不用大整数——DPD 把系数存成 `std::vector<int>` 十进制数字数组，逐位乘法+进位。两条路线独立。实测 DPD128 比 BID Dec128 还快，因为 UInt256 的 Schoolbook 乘法延迟还是比 DPD 的逐位十进制乘法高。

## 自测

`tests/tmp/uint_selftest.cpp` 是 10 项断言的独立 self-test：mul64 对照 `__int128`、mul128、div10 余数、add_small 进位、shr/shl 往返、to_string/from_dec_string 往返、cmp 顺序。全过后打印 `UINT_SELFTEST OK`。

## 局限性

- **没有符号位**：纯无符号。dec128 的符号存在 BID 位串最高位，不放在 UInt256 里。
- **没有减法、没有通用大除法**：按需再补。
- **`mul` 截断低 256 位**：256×256 的高 256 位丢弃。对 dec128（110×110=220 位）够。
- **`div_small` 是逐位试商**：比 `div10` 慢，但通用（除数可以是任意 64 位小整数）。
- **依赖 `__builtin_clzll`**：GCC/Clang 专属，MSVC 不支持（项目本就排斥 MSVC）。
