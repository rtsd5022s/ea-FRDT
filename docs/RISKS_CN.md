# 使用本工具的后果与代价

本文档不夸大事态，也不淡化风险。它讲清楚一件事：ea-FRDT 是一个故意把 CPU 推到极限的工具，你按下回车的那一刻起，你就要为这台机器发生的一切负责。不是免责声明式的套话，是具体的、已经发生过的、可以复现的代价清单。

## 一、硬件层面的代价

### 1.1 电

CPU 满载时的功耗是空闲时的 4 到 8 倍。i7-6700 空闲大概 6 瓦，满载跑到 91 瓦。这还不算主板、内存、风扇的额外开销。一台台式机满载一小时，电表走 0.1 度电。跑一晚上 8 小时，0.8 度电。按民用电价算，一晚几毛钱，看起来不多。但如果你在服务器上跑，一台 2U 双路满载功耗 600 瓦起，跑一天 14 度电，一个月 420 度，按商业电价 1 块钱一度，一个月 420 块。跑一年就是 5000 块电费。这还没算散热和机柜成本。

笔记本更夸张。游戏本满载 CPU+GPU 双烤时适配器功率 180 瓦起，电池根本供不上，适配器直接发烫。如果你用电池模式跑，电池掉电极快，而且因为 CPU 睿频在电池模式下本身就会被限制，测出来的速度比插电慢，你以为是代码问题，其实是电池撑不住。

### 1.2 散热和噪音

CPU 满载产生的热量必须被带走。台式机原装散热器（Intel 盒装那种铝块风扇）压 i7-6700 满载，风扇转速直接拉到 2500 转以上，噪音在 40 分贝以上。在安静的房间里，这个噪音相当于一台吸尘器在隔壁开。水冷会安静一些，但水泵本身也有噪音，而且水冷漏液是另一个风险。

笔记本更糟。笔记本的散热设计是给"偶尔满载"用的，不是给"连续满载几小时"用的。跑 10 分钟后散热鳍片温度上去，风扇转速拉到 5000 转，出风口吹出来的风是烫的。跑半小时以上，键盘面温度能到 45 度以上，手腕放上去是烫的。长期这样跑，硅脂会干得更快，散热垫会老化，笔记本的散热寿命会缩短。

### 1.3 降频和硬件寿命

CPU 有温度保护。温度到 95 度以上会开始降频，从 4.0 GHz 降到 3.5 GHz、3.0 GHz、2.5 GHz，直到温度降到安全范围。这意味着你跑压测跑了半小时后，测出来的 steps/sec 已经不是峰值了，是降频后的数字。你以为是代码慢了，其实是 CPU 在自我保护。

更长期的代价是硬件寿命。CPU 设计寿命是按"典型工作负载"算的，典型工作负载意味着大部分时间 CPU 在空闲或轻载，偶尔满载。如果你天天把 CPU 跑满 24 小时，电子迁移、电迁移（electromigration）会加速。CPU 不会明天就坏，但 5 年后你的 CPU 可能比正常使用的 CPU 先出故障。这个代价是隐性的，你看不到，但它在发生。

硬盘也是。压测本身不怎么读硬盘，但 Windows 在 CPU 满载时会做后台更新、杀毒扫描，这些会产生磁盘 IO。如果你的系统盘是 SSD，长期高负载下 SSD 的写入量会上去，写入寿命（TBW）会消耗。机械硬盘的马达和磁头在震动环境下长期运行也会有磨损。

### 1.4 电源

电源是最容易被忽略的。CPU 满载时电流波动很大，睿频时瞬间电流能到平时的 2 倍。一个劣质电源（杂牌 500 瓦）在这种波动下可能输出不稳定，轻则死机重启，重则损坏其他硬件。如果你用的是老电源（5 年以上），电容已经老化，满载时的纹波可能超标。跑压测前先确认你的电源额定功率留了足够余量，不是"刚好够"，是"留了 30% 余量"。

## 二、操作系统层面的代价

### 2.1 系统卡顿

这是最直接的。8 核 CPU 跑 8 个 worker，每个 worker 绑定一个核并提到实时优先级（THREAD_PRIORITY_TIME_CRITICAL）。Windows 的调度器会优先满足高优先级线程，其他进程（包括资源管理器、杀毒软件、输入法、浏览器）会被挤到剩下的核上跑。如果 8 个核全被占了，其他进程只能在时间片夹缝里跑。

实际体验是：鼠标拖动有延迟，窗口切换要等几秒，打字都卡。你想按 Ctrl+C 停掉工具，终端可能要等 1 秒才响应。这不是 bug，是绑核加实时优先级的预期行为。如果你想边跑压测边用电脑，就少绑几个核，比如 4 核 CPU 只跑 `-j 1-2`，留两核给系统。

### 2.2 后台任务被饿死

Windows Update、Defender 全盘扫描、OneDrive 同步、浏览器更新检查，这些后台任务在 CPU 满载时会被饿死。它们不是不跑，是跑不动。压测跑了一晚上，你第二天发现 Windows Update 还在下载昨天的更新，OneDrive 昨晚的文件同步没完成。这不是系统坏了，是后台任务没抢到 CPU 时间。

杀毒软件在 CPU 满载时会开始扫描工具生成的临时文件（虽然这个工具几乎不写文件），扫描本身也吃 CPU，和 worker 抢资源。建议压测时暂时关掉实时防护，跑完再开。

### 2.3 看门狗和系统保护

Windows 有 watchdog 机制。如果系统关键进程（比如窗口管理器 dwm.exe）太久没被调度，系统会触发看门狗重启。在极端情况下（比如你在一个 2 核虚拟机里跑 2 个实时优先级 worker），dwm 可能饿死，直接蓝屏。这不是常见情况，但在小核数机器上要小心。

Linux 也有类似机制。systemd-udevd、watchdogd 在 CPU 满载时如果没及时响应，会触发硬件看门狗重启。容器里跑压测要特别注意，容器的 CPU 配额限制（cgroup）和绑核是两回事，绑核绑到容器外的核上会出奇怪问题。

### 2.4 网络和其他外设

CPU 满载时，网络栈处理中断的能力会下降。你在压测时通过 SSH 连到这台机器，SSH 响应会变慢，甚至超时断开。网络文件共享（SMB/NFS）的延迟会上去。打印机、USB 设备的响应也会变慢。这些不是工具直接造成的，是 CPU 被占满后整个系统响应能力下降的连锁反应。

## 三、数据和工作的代价

### 3.1 未保存的工作

如果你在跑压测的时候，另一个窗口里有个没保存的 Word 文档、没提交的代码、没渲染完的视频，系统卡顿可能导致这些应用看起来"未响应"。你以为它死了，强杀进程，结果工作丢了。压测不会直接搞坏你的应用，但系统卡顿会诱导你做出误操作。

开始压测前，保存所有工作，关掉不需要的应用。这是常识，但很多人就是忘。

### 3.2 崩溃和重启

极端情况下系统会蓝屏或自动重启。未保存的数据会丢。如果是 SSD，突然断电（虽然是软件重启不是断电）理论上不会丢数据，但文件系统可能不一致，下次开机要做磁盘检查。磁盘检查本身要读全盘，SSD 还好，机械硬盘要等很久。

### 3.3 多租户环境

如果你在一台共享服务器上跑这个工具，你占满了 CPU，其他用户的进程会变慢。这不是你的机器，你没资格这么干。共享服务器上跑压测前先和管理员打招呼，或者在自己的容器里跑（限制 CPU 配额）。不要在生产环境跑这个工具，生产环境跑了就是事故。

## 四、DPD 格式的额外代价

DPD 格式（dpd32/dpd64/dpd128）比 BID 慢 20 到 30 倍。这个慢不是"代码写得不好"，是算法复杂度决定的：DPD 要在十进制数组上做逐位乘法、进位、舍入，还要做 DPD 三元组编解码查表。纯软件整数运算，没有硬件加速。

这意味着什么？如果你在 `-m all` 里加了 DPD 格式，那个 worker 会比其他 worker 慢一个数量级。其他 worker 几秒钟跑完自己的格式链，DPD worker 要跑几分钟甚至几十分钟。你以为工具卡住了，其实它在老老实实算 DPD。更糟的是，DPD worker 占用 CPU 的时间更长，意味着你的机器要满载更久，散热、电费、噪音的代价都翻倍。

DPD 启动前会弹黄色警告，等 10 秒按 y 确认。这个警告不是装饰，是真的要让你想清楚：你确定要为了一个 DPD 测试让机器多跑半小时满载吗？

## 五、无限循环和超时

`-l -1` 是无限循环。如果你没配 `-t`，这个工具会永远跑下去。本地跑还好，你看到了按 Ctrl+C 就行。但如果你通过 SSH 在远程机器上跑，SSH 断了（网络抖动、笔记本合盖），SSH 进程死了，工具进程不会死，它变成孤儿进程继续吃 CPU。你下次 SSH 上去，发现 CPU 100%，ps 一下才看到这个孤儿进程。

更糟的是，如果你用 nohup 或 systemd-run 把它放到后台，它会作为服务一直跑，重启机器才停。这不是假设，是真有人这么干过。

**规则：`-l -1` 永远配 `-t`。** 超时到了工具自己退出，不需要你盯着。

## 六、测量本身的代价

压测的目的是测量。但测量本身会引入干扰：

- **热干扰**：跑了几分钟后 CPU 温度上去，降频，速度变慢。你测的不是"峰值速度"，是"热平衡后的速度"。
- **调度干扰**：其他进程（杀毒、更新、同步）在后台抢 CPU，测出来的速度波动大。要干净的测量环境，关掉后台服务。
- **频率波动**：CPU 睿频不是恒定的。轻载时 4.0 GHz，满载时可能 3.5 GHz，温度上去后 3.0 GHz。你测出来的 steps/sec 是整个过程的平均值，不是某一时刻的瞬时值。
- **缓存冷热**：每个格式切换时，CPU 缓存是冷的，前几步速度慢。你看到的速度曲线是"爬升→稳定→降频"，不是一条直线。

这些干扰不是工具能消除的，是物理现实。你要做的是理解这些干扰，不要把测出来的数字当成绝对真理。

## 七、心理和时间的代价

压测看起来是"让它跑着就行"，但实际上你要盯着它：

- 看监视器确认它在正常跑，没卡住。
- 看温度（如果你装了监控软件）确认没到危险值。
- 听风扇噪音确认没出现异常异响。
- 准备好 Ctrl+C 随时停。

这不是"跑着不管"的任务，是"跑着盯着"的任务。你花在盯压测上的时间，本可以用来写代码、读论文、休息。跑一次 10 秒的压测无所谓，跑一次 2 小时的压测，你等于花了 2 小时在旁边等。

## 九、什么情况下你应该跑这个工具

说了这么多代价，不是让你别用。是让你在跑之前想清楚：你为什么要跑？

- 你在验证一个浮点格式的行为，需要知道它从 1.0 到溢出要多少步——跑。
- 你在调试编译器，想看 x87 在某一步的位型——跑。
- 你在压测系统稳定性，想看满载下会不会崩——跑，但在测试机上跑。
- 你就是想看看 CPU 跑满是什么感觉——跑，但跑 10 秒就停，别跑一天。

不要在生产环境跑，不要在你不知道会发生什么的机器上跑，不要在你没有权限的机器上跑。

## 十、跑完之后

跑完压测后，做这几件事：

1. 确认进程已经退出（任务管理器看 CPU 使用率回到正常）。
2. 如果跑了很久，让机器空闲 10 分钟散热。
3. 保存你的测量数据（截图或重定向到文件）。
4. 如果是笔记本，插上电源，让电池充一会。
5. 如果系统有任何异常（蓝屏、重启、文件丢失），检查磁盘和备份。

这个工具是一把手术刀，不是一把锤子。用对了地方它帮你看清浮点格式的边界，用错了地方它就是个耗电的玩具。
