# 工作原理

本文讲清楚 ea-FRDT 是怎么把一个浮点数从 1.0 一路逼到溢出的：从最底层位表示讲到多线程 worker 池与监视器。不假设读者看过代码，但假设读者知道 IEEE 754 浮点。

## 一、问题本身

任何浮点格式都有上下限：最大有限值与最小正正规格数。从 1.0 出发，每步乘大于 1 的系数（默认 1.02）单调上升，直到下一步变无穷；乘小于 1 的系数则单调下降，直到下溢到零。

每一步做三件事：

1. **计算下一步**：当前值乘系数。
2. **判断退出**：下一步是否 infinity、zero、或与当前值相同（identity）。
3. **打印当前值**：按显示格式渲染，可选 `--bits` 追加 hex/bin 位型。

格式差异全在第 1、2 步：二进制浮点用 IEEE 754 sign/exponent/mantissa 三段；十进制浮点分 BID、DPD；自写格式（FP4、FP8 等）用整数位域直接仿真。ea-FRDT 把它们统一到同一个驱动器。

## 二、统一驱动器

核心驱动器在 `drive.h`，是模板函数 `drive_core`，由各格式提供 lambda：

- `next(s)`：算出下一步 `nxt`。
- `isInf(nxt)` / `isZero(nxt)` / identity 判断：退出谓词。
- `render(s)`：渲染当前值为字符串。
- `extra(s)`：附加信息（如 BID 系数、DPD 位数组）。

驱动器不知道在跑哪种格式，只循环：调 `next`、判退出、更新当前值、打印、睡 `delay_ms`、查超时。格式逻辑全在 lambda 里。好处是加格式不动驱动器；代价是模板膨胀，但每种格式只实例化一次，体积可接受。

退出原因共七种枚举：

- `overflow->inf`：`next` 返回 infinity。
- `underflow->0`：`next` 返回 zero。
- `identity->stop`：`next` 等于当前值（无进展）。
- `safety->limit`：撞到 `2^120` 步数计数器，防跑飞。
- `timeout`：全局超时 atomic 到点。
- `nan->nan`：下一步变 NaN（仅原生路径；自写整数格式不产生 NaN）。
- `fixed`：opt-in `--steps <n>` 跑满 N 步退出（JSON token `fixed`、终端文案 `fixed-steps`）；未指定该开关则不出现。

外层控制文案 `cancelled`（确认被拒/超时）、`sigint`（Ctrl+C）不是枚举原因。

静默 `-q` 下驱动器抑制实时行与结束行，结果写入 `RunResult`，退出时只留一行 `总计 <N> 步 · <退出原因> · 墙钟 <t>` 尾行（`--json` 不打印；`--dump`/`--dump-events` 隐式静默但保留）；普通模式每步用 `\r` + `\033[K` 原地刷新，超宽换行。

驱动器把 `extra` 与 dump 回调做成模板参数（`no_extra_fn`/`no_dump_fn` 为编译期缺省），因此热路径没有 `std::function` 的类型擦除与间接调用；`--steps` 上限在记录落盘之前检查，与自然终止同序。

## 三、二进制浮点格式

### 3.1 原生格式

`fp16`/`fp32`/`fp64` 用原生类型：fp16 在 Clang 下为 `_Float16`、GCC 下为 `std::float16_t`，fp32/fp64 为 `float`/`double`。

步进即 `next = s * factor`，退出判断用 `std::isinf` 与 `s == 0.0`。ULP 模式：`mululp` 乘 `1 + 1 ULP`；`addulp` 尾数加 1 ULP；`subulp` 尾数减 1 ULP（递减）。

### 3.2 自写位级格式

`fp4`(E2M1)、`fp6`(E3M2)、`fp8-e4m3`、`fp8-e5m2`、`bf16`、`tf32` 无原生硬件支持，由 `formats/engine_sim.h` 的 `SVal` 仿真：

```cpp
struct SVal {
    bool sign;
    int exp;
    uint64_t man;
};
```

`SVal` 存解码后的 sign/exponent/mantissa，不是打包位型。乘法手写：符号异或、指数相加减 bias、尾数相乘再归一化（找乘积最高位、右移对齐、指数补偿）。这里要正确处理 subnormal（指数 0 时前导零）、overflow（超 Emax）、underflow（低于 Emin），边界逐类判断。

### 3.3 x87 80 位扩展精度

x87 为 1 符号、15 指数、64 尾数（无隐含前导 1，显式存储）。不用 `long double`（各编译器/目标位宽不一、不可移植），而是手写 80 位整数仿真：尾数为单个 64 位字、指数为小整数，64×64 尾数中间积借助 `unsigned __int128`，乘积后归一化。

### 3.4 FP128 binary128

binary128 为 1 符号、15 指数、112 尾数，是最复杂的纯软件格式；112×112 尾数乘积需宽中间积，实现用编译器 `__int128` 承担 64×64 中间乘积，拆成 64 位段做 schoolbook 并按位宽累加。早期版本用 `v << sh` 左移，高位溢出时行为错误，后改为掩码拆分 + 右移进位。归一化与舍入把宽乘积舍回 112 位，舍入进位可能顶到尾数最高位，需回调指数。

## 四、十进制浮点格式

IEEE 754-2008 定义 BID 与 DPD 两种十进制编码，两条路线均实现。

### 4.1 BID 路线

BID 系数存为普通二进制整数：dec32 至多 7 位十进制（约 24 位），dec64 至多 16 位（约 54 位），dec128 至多 34 位（约 113 位）。dec32/dec64 系数放 `uint64_t`；dec128 用自研 `UInt256`（`uint256.h`，纯 `uint64_t` 数组 + schoolbook 乘法）。布局为 1 符号 + 组合字段 + 系数；组合字段区分 NaN/无穷/有限及首数位类别。乘法 = 整数相乘 → 数十进制位数 → 调指数 → 按需右移舍入。

### 4.2 DPD 路线

DPD 把十进制数字三个一组（0–999）编成 10 位二进制（1000 值 vs 1024 编码空间，余码处理数字为 8/9 的情况）。单 declet 编解码在 `formats/engine_dpd_codec.h`；多 declet 打包、定长对称 pack/unpack 子单元与启动自检在 `formats/engine_dpd.h`。编码取 d2 d1 d0（各 4 位 BCD），判哪些 ≥8，查组合表得 10 位 DPD；解码反向。

`DpdNum` 存 `std::vector<int>` 十进制数字，乘法乘小整数、低位到高位进位；除以 10^k 即数字右移 k 位，舍入看被丢最高位。打包成 32/64/128 位用于 hex/bin 显示与 `--dump` 记录；对称 pack/unpack 子单元支撑启动真实往返自检（`[DPD-SELFCHECK] OK`）。DPD 无硬件 FPU，弱机满载更久。

### 4.3 IEEE 754 边界值

| 格式 | 位数 | 十进制位数 | Emax | Emin |
|---|---|---|---|---|
| dec32 | 32 | 7 | 96 | -95 |
| dec64 | 64 | 16 | 384 | -383 |
| dec128 | 128 | 34 | 6144 | -6143 |

溢出判据不是“指数 > Emax”，而是最高位指数 `exp10 + digits - 1 > Emax`。例：dec32 系数 1234567（7 位）、exp10=90，最高位指数 90+6=96=Emax，合法；乘一步变 12345670（8 位）即使右移回 7 位，最高位指数已超 Emax，须判溢出。

## 五、UInt256 大整数

`uint256.h` 的 `UInt256` 是四个 `uint64_t` 组成的 256 位无符号整数；schoolbook 乘法：两 4 段得 8 段乘积，按位累加、进位上传。它刻意不依赖 `__int128`（可移植、无 UB）；`__int128` 只用于步数计数器、x87 与 fp128 的尾数中间积，不用于十进制系数。`div10` 从高位除下、余数即该位十进制数字，供 dec128 计数位数并调指数。

## 六、多线程并发模式

单格式跑完一种即退出。`-m all` 起 N 个 worker，各自独立跑默认 13 格式链（排除 DPD32/64/128 与 Dec128，`--only` 加入）。

### 6.1 WorkerSlot

`alignas(64)` 对齐一个缓存行，存格式 ID、当前值字符串、步数（u128）、耗时、完成标志、退出原因，消除多核伪共享。

### 6.2 绑核

Windows `SetThreadAffinityMask` + `THREAD_PRIORITY_TIME_CRITICAL`；Linux `pthread_setaffinity_np` + best-effort `SCHED_BATCH`/`nice(-5)`；启动时绑核；失败（容器/VM/无权限）降级不绑。目的主要是降低调度抖动、让 steps/sec 稳定。

### 6.3 值拷贝

worker 拿到 `RunParams` 与格式链 vector 的拷贝，不引用 main 栈变量；只写自己的 Slot，监视器只读，无需互斥锁。

### 6.4 监视器

主线程按 `-r` 间隔（`-m all` 默认 1000 ms）扫描 Slot，打印 `[wN] 格式: 当前值 steps/s 已用时长 loop=X/Y`；时间逐层 Y/M/D/H/M/S/ms，`\r` 原地刷新，每 worker 一行。

### 6.5 汇总表

全部 worker 完成（或超时）后，每 worker 每格式一行：步数、耗时、退出原因；末行为全局总步数与总吞吐。

## 七、输入校验和安全

启动分层校验：

- 未知格式/开关、起点无法解析、畸形 `0x`、特殊起点冲突 → 硬退出 `2`（stderr）。
- 倍率为 0/负/NaN/Inf → 硬退出 `2`。
- `-l -1` 配 `-t 0`：`-m all` 下一级黄色确认警告（警告而非拒绝，建议配超时）。
- 倍率 `< 1e-10`：一级警告（所需步数可能极大）；`2^120` 计数器兜底。
- 纳入 DPD×3 / Dec128：`-m all` 下二级红色 `[!!!]` 确认，10 秒内按 `y`，否则 `cancelled`。

早期版本缺无限循环守卫，曾在 SSH 断开后留下孤儿进程整夜满载。

## 八、双语和颜色

界面文字走 `tr(zh, en)`，由全局 `g_lang` 选择（默认 `zh`）。颜色常量在 `color.h`：青横幅、灰信息、绿正常、黄警告、红错误。Windows 下在 `#ifdef _WIN32` 设置 UTF-8 代码页与虚拟终端处理。

## 九、总结

核心思路是把每种浮点格式逼到物理极限、观察其崩坏方式：驱动器统一格式，模板消除重复，自写格式摆脱厂商库依赖，worker 池压测系统极限。它不是温和基准，而是魔鬼高压测试工具——设计上让 CPU 跑满、让格式崩给你看。
