# 工作原理

## 这个程序到底在干什么

从一个浮点数出发，按固定倍率一步一步走，直到走到溢出变成无穷大，或者下溢变成零。每走一步都记录步数、当前值、耗时。支持 17 种浮点格式，单线程顺序走，或者多线程同时跑完全部格式。

本质上是在测每种浮点格式从 1.0 走到溢出需要多少步，以及走的过程中每一步的值长什么样。不同格式的精度不同，能表示的数的范围不同，步数差异很大。FP4 只有 4 位，一步就炸；FP128 有 112 位尾数，要走几十万步。

程序的核心循环非常简单：拿当前值，乘倍率，检查溢出/下溢，打印，再循环。但围绕这个核心循环，外围包了一层又一层：参数解析、格式分发、多线程调度、实时显示、超时控制、循环、跨平台抽象、十进制浮点编解码、大整数运算。整个项目从最初的"从 1 数到 inf"演变成现在这个样子，每一层都是后来加的。

## 浮点格式怎么组织

17 种格式分四类，代码里用一个枚举 `FmtId` 串起来：

```
enum class FmtId {
    FP4, FP6, FP8E4M3, FP8E5M2,
    FP16, BF16, TF32, FP32,
    DEC32, DPD32,
    FP64,
    DEC64, DPD64,
    X87, FP128,
    DEC128, DPD128
};
```

这个顺序就是 `-m all` 模式下每个 worker 跑格式链的顺序。从小到大，先小格式后大格式。小格式先炸，大格式后炸。

### 原生格式

FP16、FP32、FP64。直接用编译器原生类型，不自己实现位运算。

FP16 是 `_Float16`，GCC 和 Clang 在 13/16 版本以上原生支持。内存布局是 16 位：1 符号 + 5 指数 + 10 尾数。Exponent bias 是 15。Emax=15，emin=-14。最大正规格化数是 65504，最小正规格化数是 6.1035e-5。

FP32 就是 `float`，32 位：1 符号 + 8 指数 + 23 尾数。Bias 127。Emax=127，emin=-126。最大值 3.4028e38，最小正规格化 1.1755e-38。

FP64 就是 `double`，64 位：1 符号 + 11 指数 + 52 尾数。Bias 1023。Emax=1023，emin=-1022。最大值 1.7977e308，最小正规格化 2.2251e-308。

这三个格式的驱动器是模板函数 `run_native<T>`，传入类型参数就行。函数内部用 `std::nextafter` 或者直接乘法。步进逻辑就是 `x = x * factor`，然后检查 `std::isinf(x)` 判断溢出。

### 自写位级格式

FP4(E2M1)、FP6(E3M2)、FP8-E4M3、FP8-E5M2、BF16、TF32。这六个格式编译器没有原生类型，全部手写位运算。

每个格式用一个结构体 `SVal` 表示，内部存一个无符号整数（原始位模式）。SVal 的模板参数是总位数：

```cpp
template<int BITS>
struct SVal {
    uint64_t raw;
    // ... 操作函数
};
```

操作就是位操作：

- 取符号位：`(raw >> (BITS-1)) & 1`
- 取指数字段：`(raw >> mant_bits) & exp_mask`
- 取尾数字段：`raw & mant_mask`
- 组装：`(sign << BITS-1) | (exp << mant_bits) | mant`

每种格式的位布局：

**FP4 (E2M1)**：4 位，1 符号 + 2 指数 + 1 尾数。Bias 1。Emax=1。最大值 3.0。最小正规格化 0.5。

**FP6 (E3M2)**：6 位，1 符号 + 3 指数 + 2 尾数。Bias 3。Emax=3。最大值 28.0。最小正规格化 0.25。

**FP8-E4M3**：8 位，1 符号 + 4 指数 + 3 尾数。Bias 7。Emax=8。最大值 448.0。这是 NVIDIA 用的格式。

**FP8-E5M2**：8 位，1 符号 + 5 指数 + 2 尾数。Bias 15。Emax=16。最大值 57344.0。这是 IEEE 标准的 FP8 格式。

**BF16**：16 位，1 符号 + 8 指数 + 7 尾数。Bias 127。Emax=127。指数范围和 FP32 一样，但尾数只有 7 位。最大值 3.3895e38。这是 Google Brain 搞出来的格式，深度学习常用。

**TF32**：19 位，1 符号 + 8 指数 + 10 尾数。Bias 127。指数和 FP32 一样，尾数折中。最大值和 FP32 差不多。这是 NVIDIA Ampere 架构用的格式。

步进用 `nextafterT` 的思路：从 x 走到相邻的下一个可表示的数。具体做法是把 raw 当成整数加 1（或者减 1），然后处理边界：

- 如果符号位是 0（正数），raw++
- 如果符号位是 1（负数），raw--
- 当 raw 跨过 0 时，处理符号翻转
- 当指数字段全 1 时，已经是 inf，停住
- 当指数字段全 0 时，是非规格化数，也能继续走

### 纯软件格式

x87（80 位扩展精度）和 FP128（128 位，112 位尾数）。这两个格式编译器没有原生类型，也不用 long double（msys64 的 long double 是 80 位但有 libquadmath 依赖问题），全部手写纯整数运算。

x87 用 80 位：1 符号 + 15 指数 + 64 尾数（含整数位）。Bias 16383。Emax=16383。和标准 IEEE 格式不同的是，x87 的尾数有一个显式的整数位（显式 leading bit），所以即使指数是 0 也不表示非规格化数。

FP128 用 128 位：1 符号 + 15 指数 + 112 尾数。Bias 16383。和 IEEE binary128 一致。但不用 libquadmath，全部手写。

内部用两个 64 位整数（高低段）表示：

```cpp
struct Q128 {
    uint64_t hi, lo;
};
```

乘法是 128 位乘 128 位得 256 位，然后截断舍入到 113 位。加法需要对齐指数，然后加尾数。比较大小先比符号，再比指数，再比尾数。

这部分代码在 `fp_formats.h` 里，是整个项目最底层的数学部分。最开始这部分用 `__int128`，后来加了自研的 UInt256 大整数作为替代。

### 十进制浮点

Dec32/Dec64/Dec128 走 BID 路线，DPD32/DPD64/DPD128 走 DPD 路线。两组都是 IEEE 754-2008 标准定义的十进制浮点编码，但编码方式不同。

**BID (Binary Integer Decimal)**：系数用二进制大整数存，指数单独存。Dec32 系数最多 7 位十进制数字（需要 24 位二进制），Dec64 16 位（54 位二进制），Dec128 34 位（113 位二进制）。

Dec32 的位布局：32 位，1 符号 + 11 组合字段 + 20 系数。组合字段是 5 位 combo + 6 位指数 continuation。指数 bias 是 101。Emax=96，emin=-95。

Dec64：64 位，1 符号 + 13 组合字段 + 50 系数。Bias 398。Emax=384，emin=-383。

Dec128：128 位，1 符号 + 17 组合字段 + 110 系数。Bias 6176。Emax=6144，emin=-6143。

BID 的乘法就是大整数乘法乘完后调指数，然后舍入到最近的 10 的幂。Dec128 的系数需要 113 位二进制，用自研的 UInt256 大整数类实现。

**DPD (Densely Packed Decimal)**：每 3 位十进制数字用 10 位二进制编码（declet）。系数是一串 declet 串联起来的。Dec32 有 7 位十进制数字，需要 3 个 declet（第一个 declet 只编码 1 位，后面两个各 3 位）。

DPD 的编解码需要查表（IEEE 754-2008 标准决策表）。输入一个 3 位十进制数（000-999），输出对应的 10 位二进制。反过来也有表。

DPD 比 BID 复杂，但在大系数时压缩率更好：BID 是 3.32n 位（n 位十进制），DPD 是固定 3.33n 位。小系数时 BID 更省（1 只需要 1 位，DPD 固定 10 位）。

BID 代码在 `decimal.h`，DPD 代码在 `dpd.h`。两条路线完全独立，互不依赖。代码里留了一个枚举位以后可以切换编码模式，但目前 DPD 是独立头文件。

## 步进逻辑

每一步做什么？三种步进模式：

### ×倍率（默认）

当前值乘上倍率 k（默认 1.02）。这是最简单的模式，走的步数由 k 决定。k=1.02 意味着每步增长 2%，大约 50 步翻倍。

倍率乘完之后要处理溢出：如果乘完的值超过格式能表示的最大值，就标记为 overflow->inf，这一轮结束。

如果 k < 1，值递减，会走到下溢。下溢到 0 时标记为 underflow->0。

### mululp

每步加一个 ULP 的倍率。具体是 `x = x * (1 + 1 ULP)`。这个模式走的步长更细，在精度边界附近能看到更细的变化。

ULP 的大小取决于当前值的量级。同样是 1 ULP，在 1.0 附近和在 1e30 附近差很多倍。mululp 模式下，步长会随着值变大而自动变大。

### addulp

每步加一个 ULP。`x = x + 1 ULP`。直接跳到下一个可表示的数。这个模式步数最多，因为每步只动一个最小单位。

addulp 模式下，从 1.0 走到 inf 要走的步数大约是尾数位数的量级。FP32 有 23 位尾数，所以大约走 2^23 ≈ 800 万步。

## 起点

从哪里开始走？几种选项：

- 默认从 1.0 开始
- `-a min-normal`：从最小正规格化数开始。这个数是格式能表示的最小的非零正规格化数
- `-a max-finite`：从最大有限数开始（配合 k<1 递减）。从最大值往下走，一直走到 0
- `-a 0x...`：从指定的原始位模式开始。比如 `-a 0x3f800000` 就是 FP32 的 1.0
- `-a 数字`：从指定十进制数开始（支持科学计数法，比如 `-a 1.5e-3`）
- 支持负数起点，比如 `-a -1`

起点解析在 `format_util.cpp` 的 `parse_number` 里，能识别：

- 纯十进制：`1.5`, `0.001`
- 科学计数法：`1.5e-3`, `2E5`
- 工程计数法：`1k`, `2M`, `3G`（后缀）
- 十六进制 Raw：`0x3f800000`

解析逻辑是先看字符串开头，如果是 `0x` 就按十六进制读。否则按十进制读，识别 `e` 或 `E` 作为指数分隔符。

## 显示格式

三种显示格式：

- 工程计数法（默认）：`1.234567e+10`，尾数 6 位小数
- 科学计数法：和工程类似，但指数不强制 3 的倍数
- 完整显示：打印所有有效数字，不截断

小数位数由 `-d` 控制，默认 6。`-d -1` 表示完整显示，`-d 0` 表示整数部分。范围 0 到 100。

括号内位表示由 `--bits` 控制：
- `hex`：括号内显示十六进制位模式
- `bin`：括号内显示二进制位模式，符号/指数/尾数用空格分段
- `off`：不显示括号（默认）

二进制浮点的 bin 显示是三段：符号位 空格 指数字段 空格 尾数字段。十进制浮点是四段（BID 是符号/组合字段/系数，DPD 是符号/combo/declet串）。

## 多线程 ALL 模式

`-m all` 时，每个线程独立跑完整的 17 格式链。线程之间不共享状态，每个线程有自己的 WorkerSlot 结构，值拷贝参数。

线程数由 `-j` 指定：
- 单值：`-j 4` 表示只用第 4 核
- 逗号：`-j 1,3` 表示用第 1 和第 3 核
- 范围：`-j 1-4` 表示用第 1 到第 4 核
- 混合：`-j 1,3-5` 也行

`-j` 解析在 `parse_core_list` 函数里，先按逗号分割，然后每段如果有 `-` 就按范围展开。结果是一个核心编号列表，编号从 1 开始。

每个线程绑核：Windows 用 `SetThreadAffinityMask`，Linux 用 `pthread_setaffinity_np`。跨平台逻辑在 `platform.h` 里隔离。

WorkerSlot 用 `alignas(64)` 对齐到缓存行大小，避免多核之间的伪共享（false sharing）。每个 worker 的数据结构独占一个缓存行，不会因为多核同时读写导致缓存乒乓。

WorkerSlot 的结构：

```cpp
struct alignas(64) WorkerSlot {
    RunResult cur;
    std::vector<RunResult> done;
    int loop_done = 0;
    u128 total_steps = 0;
    std::vector<u128> sum_steps;
};
```

`cur` 是当前格式的运行结果，`done` 是这一轮所有格式的结果列表，`total_steps` 是累计总步数，`sum_steps` 是每个格式累计了多少步。

## 监视器

主程序起一个监视器线程，定期刷新屏幕显示每个 worker 的状态。刷新间隔由 `-r` 控制，`-m all` 模式默认 1 秒刷新一次，单线程模式默认每步刷新。

监视器显示每行格式：
```
[w1] FP32: 1.234567e+10   4500000 steps/s   1.234s   loop=1/3
```

各列：
- `[w1]` worker 编号
- `FP32:` 当前格式名
- `1.234567e+10` 当前值
- `4500000 steps/s` 当前速度
- `1.234s` 当前格式耗时
- `loop=1/3` 当前循环次数

时间显示是逐层的：如果总耗时不到 1 分钟，只显示秒；超过 1 分钟显示分:秒；超过 1 小时显示 时:分:秒；超过 1 天显示 天:时:分:秒。

## 汇总表

所有 worker 跑完后，打印汇总表。每个 worker 一节：

```
--- worker 1 ---
格式        单次步数    累计步数    退出           耗时ms   总耗时
FP32        4481        13443       overflow->inf  0.5      1.5
FP64        35843       107529      overflow->inf  4.2      5.7
...
```

列说明：
- 格式名
- 单次步数：这一轮循环走了多少步
- 累计步数：所有循环加起来
- 退出原因：overflow->inf / underflow->0 / timeout / cancelled
- 单次耗时：这一轮这个格式跑了多久
- 总耗时：从开始到现在的墙钟时间

最后一行是总计：总步数、总墙钟时间、平均速度。

## 循环

`-l` 参数控制循环次数：
- `-l 1`：跑一遍就停（默认）
- `-l 3`：跑 3 遍
- `-l -1`：无限循环，直到超时或 Ctrl+C

循环模式下，每跑完一遍格式链，重置状态重新开始。`done.clear()` 在每轮开始时调用，清空上一轮的结果。汇总表的"单次步数"是最后一遍的步数，"累计步数"是所有遍加起来。

无限循环 `-l -1` 必须配合 `-t` 使用，否则会永远跑下去。Ctrl+C 也能停。

## 超时

`-t` 参数设置超时秒数。`-t 0` 表示不限制（走到溢出或下溢为止）。

超时检查在每个 worker 循环里做：每个格式开始前，检查全局超时时间戳，如果已经超时就 break。跨格式、跨循环都生效。

超时是全局的：所有 worker 共享同一个 `g_timeout_sec` 和 `t0`。任何一个 worker 发现超时，就退出循环，等其他 worker 也退出后打汇总表。

## Ctrl+C

收到 SIGINT 信号时，设置一个全局标志 `g_sigint`。worker 在每步检查这个标志，发现后退出循环。监视器也会检测到，打印"程序提前退出（收到 Ctrl+C）"。

信号处理函数是简单的：

```cpp
void on_sigint(int) {
    g_sigint = true;
}
```

不做复杂的清理，只设标志位。worker 在下一个检查点看到标志就退出。

## 跨平台层

Windows 和 Linux 的系统 API 不同，代码里全部隔离在 `platform.h` / `platform.cpp` 里：

- 绑核：Win 用 `SetThreadAffinityMask`，Linux 用 `pthread_setaffinity_np`
- 高精度定时器：Win 用 `timeBeginPeriod(1)` 把系统定时器分辨率提到 1ms，Linux 内核本身就是高分辨率不需要
- 核心数：Win 用 `GetSystemInfo` 拿逻辑核心数，`GetLogicalProcessorInformation` 拿物理核心数；Linux 用 `sysconf(_SC_NPROCESSORS_ONLN)`

接口是统一的：

```cpp
namespace fw::plat {
    void bind_thread_to_core(int core_id);
    void set_high_res_timer();
    void reset_high_res_timer();
    int  logical_cores();
    int  physical_cores();
}
```

核心数学代码（浮点格式、十进制编码、大整数）全部是纯 C++，不依赖任何系统头文件。只有线程绑定和定时器这部分走 platform 层。

## 数据结构

项目里的核心数据结构有几个：

**RunResult**：一次格式运行的结果。记录格式名、当前值字符串、步数（u128 128位无符号整数，防止溢出）、退出原因枚举、耗时毫秒数。

**u128**：128 位无符号整数，用两个 uint64_t 高低段实现。支持加法、乘法、比较。步数统计用它，因为跑几亿步会超过 64 位。

**RunParams**：运行参数包。把倍率、起点类型、步进模式、显示格式、小数位数、位表示模式这些参数打包成一个结构体，值拷贝传给每个 worker。

**Lang 枚举**：双语切换。`Lang::ZH` 和 `Lang::EN`。所有界面文字走 `tr("中文", "English")` 函数，根据当前语言返回对应字符串。

**clr 命名空间**：ANSI 颜色常量。`clr::RED`、`clr::GRN`、`clr::YEL`、`clr::CYN`、`clr::BLU`、`clr::GRY`、`clr::RST`（重置）。打印彩色输出用。

## 编译选项

CMakeLists.txt 里的编译选项：

- `-std=c++23`：要求 C++23 标准
- `-O2`：Release 默认优化级别
- `-Wall -Wextra`：开启常用警告
- `Threads::Threads`：链接 pthread
- Windows 下链接 `winmm`（timeBeginPeriod 需要）
- MinGW 下加 `-static -static-libgcc -static-libstdc++`（全静态链接）

本地手动编译命令（不用 CMake）：

```
g++ -std=c++23 -O2 -march=native -static -static-libgcc -static-libstdc++ \
    -Iinclude src/float_inf_walk.cpp src/lang.cpp src/format_util.cpp src/drive.cpp src/platform.cpp \
    -lwinmm -o float_inf_walk.exe
```

`-march=native` 会开启本机 CPU 支持的所有指令集（AVX2 等），CI 环境不用这个因为架构不同。

## 注意事项

1. g++ 16.2.0 在 msys64 下有内部崩溃（ICE），clang 18 编译正常。CI 上用 Ubuntu 自带 g++ 和 clang，不受影响。
2. DPD 模式在并发模式下会弹黄色警告，提示性能可能慢 20-30 倍，需要按 y 确认。这是因为 DPD 编解码是查表 + 逐 declet 处理，计算量远大于 BID。
3. `-m all` 不自动包含 DPD32/DPD64/DPD128，需要手动 `-m dpd32` 单独选。这是出于性能考虑。
4. x87 和 FP128 是纯软件实现，没有用 long double，所以不依赖 libquadmath。
5. UInt256 大整数是自研的 schoolbook 乘法，没有用编译器的 `__int128`。头文件里标记了 O0 编译（避免优化器出问题）。
6. 负数起点配合 k>1 会先走到 -inf，这是正常行为。
7. CI 的 smoke test 只跑 5 秒，不会等格式自然走到溢出。完整测试用本地 `test_all.ps1`。
8. ANSI 颜色代码在不支持的终端上会显示乱码，静默模式 `-q` 可以关闭所有输出直接出汇总表。
9. `-j` 的核心编号从 1 开始，不是从 0 开始。`-j 1` 是第一个逻辑核心。
10. 循环模式 `-l -1` 配合 `-t` 使用，否则会永远跑下去。Ctrl+C 也能停。
11. `-g addulp` 和 `-g mululp` 模式下不显示倍率 x1.02，因为倍率不是 1.02 了。
12. `-s` 参数从最小非规格化数开始，比 min-normal 更小，会先走一段非规格化数才进入正规格化区间。
13. DPD 的溢出判断是 `exp10 + digits - 1 > Emax`，不是简单的 `exp10 > Emax`。因为十进制浮点的系数可能进位，需要加上有效位数。
14. BID 的 Dec128 系数用 UInt256 大整数，乘法是 schoolbook O(n^2)，比硬件乘法慢但不依赖 libquadmath。
15. 监视器的时间显示是逐层的：<1分钟只显示秒，<1小时显示分:秒，<1天显示时:分:秒，>=1天显示天:时:分:秒。
16. 汇总表的"单次步数"在循环模式下是最后一遍的步数，不是所有遍的平均。"累计步数"才是总和。
17. 线程数硬上限是 `std::thread::hardware_concurrency()`，超过会被截断。
18. `-m all` 模式下每个 worker 跑的格式链是一样的，都是 17 种格式。worker 之间不分配不同格式，每个 worker 都跑全套。
19. 颜色代码用 ANSI 转义序列，在 Windows 10+ 的终端和所有 Linux 终端上都支持。老版本 CMD 不支持会显示乱码。
20. 语言切换由 `--lang zh|en` 控制，所有界面文字都走 `tr()` 双语函数。
